The problem

Your agent tries, fails, and backtracks more than you do — and git can't see any of it

For AI-assisted work specifically, most of the useful signal never becomes a commit: an abandoned migration, three failed test runs, a decision to not change an API. Structurally, if it never reached git add, it doesn't exist in your history.

The honest comparison

We asked two agents to argue this out. Neither one folded.

Before shipping this pitch, we had one AI build the strongest case for "just use git log and markdown, skip the custom tooling" — and another build the strongest defense of monitor. Here's the actual disagreement, not a strawman.

The case for git alone

  • Git already gives timestamped, immutable, chained history — for free.
  • A good commit body convention captures DECISION/WHY with zero new file format.
  • Branch, author, and diff are already native to every commit — no separate chip to desync.
  • Every claimed capability is a presentation layer over data git already owns.

Where it breaks

  • A commit is what you chose to keep. An operation is everything that happened before that choice — failed attempts included.
  • Commit conventions have no validator across a human + an agent + another AI tool. Format drifts the moment there's more than one writer.
  • status=partial|failure can't be enforced by free-text commit messages — nothing queries "every failed attempt this week" out of prose.
  • Squash-merges erase the granular per-commit reasoning. Monitor's log is append-only by design, specifically so it survives that.
Verdict: monitor doesn't replace git — git stays authoritative for what shipped. Monitor exists for the part git structurally can't record: everything that happened before something became a commit worth keeping.
How it works

Two jobs. That's it.

No language detection, no build-command guessing, no inspecting what your project does. Log, and report. Nothing else.

1

Log — automatic, per commit

A tracked git hook calls logger.py on every commit — mechanical facts only, no agent required. Compliance isn't optional anymore; it's wired into git commit itself.

2

Log — agentic, per decision

When there's real reasoning to capture, the agent logs DECISION/WHY/GAPS/NEXT fields — validated and sanitized before they ever touch disk.

3

Report — automatic, per merge

A merge hook triggers a report — pulling every logged decision on the branch into one immutable, self-contained HTML snapshot. No manifest file, nothing to hand-maintain.

Install

One command. Nothing to configure.

As a Claude Code plugin

/plugin marketplace add owner/monitor-tools
/plugin install monitor@monitor-tools
/monitor:init

Without a marketplace

./install-monitor.sh /path/to/project

Copies the engine, nests the commands, never touches your data folder.

Being upfront

Auto-logging works for anyone who commits — that part is universal. Auto-reporting needs a branch merge to trigger. If you commit straight to main with no branches, you get logs, not reports, and that's the honest limit of this design today.
