Fix Next Steps Section: Project Actions Only, Never Chat-Turn Content

A published report's Next Steps section described the authoring agent's own conversational turn instead of a real project action. Fixed at the source template and codified as a SKILL.md rule, so every future report's Next Steps stays a list a reader can act on after the conversation has ended.

Summary

A user reviewing the branch-audit report caught a defect: its Next Steps section read "Present cleanup options to the user for explicit approval before any branch deletion or push" — a description of what the authoring agent was about to do in that chat turn, not a project or code action a reader could act on later. Fixed at the source: render_report.py's inline template comment (which regenerates monitor/reports/template.html on every render) and a new explicit rule in SKILL.md both now require Next Steps entries to be concrete project/code actions, and explicitly forbid describing the conversation that produced the report.

What Was Asked

The user flagged the leaked line as "internal thought, not something a human can take," clarified that Next Steps should describe project development next steps rather than the agent's own chat/thoughts, and asked for the relevant skill to be improved.

What Was Done

  • Updated the Next Steps inline comment in plugins/monitor/skills/monitor/scripts/render_report.py (the source that regenerates reports/template.html) to explicitly require project/code actions and forbid describing the authoring session's own turn.
  • Added a new bullet to plugins/monitor/skills/monitor/SKILL.md's reporting section stating the same rule, with the reasoning: a report is read after the turn that wrote it has ended, so mid-conversation actions (asking the user something, awaiting approval) are meaningless to a later reader.
  • Synced the fix into this repo's project-runtime engine copy (monitor/scripts/render_report.py) and regenerated monitor/reports/template.html so the fixed comment is live immediately, not just on the next full render.
  • Bumped the plugin version 1.15.1 → 1.15.2, ran the full test suite (82 unit + integration, all passing) and the thought-leak scanner (clean), then committed and fast-forwarded both dev and main.

Decisions & Rationale

  • DECISION: fix at the template-comment and SKILL.md level, not by adding a post-hoc validation script. WHY: this is an authoring-judgment problem (recognizing "this is my own chat action, not a project action"), not a mechanical pattern a regex could reliably catch without false positives against legitimate project next steps that happen to mention users or approval workflows.
  • DECISION: the already-published branch-audit report keeps its bad line, uncorrected. WHY: this repo's own rule states reports are immutable snapshots, never rewritten — the user confirmed this explicitly when asked, choosing to treat the old report as a historical artifact rather than make a retroactive exception.
