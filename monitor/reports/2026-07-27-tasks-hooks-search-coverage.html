Decisions & Rationale

  • Tasks are a separate entity, not a log field. WHY: a lifecycle (open → in_progress → terminal) with accumulating metrics doesn't fit a single log line; keeping it append-only in its own file mirrors the log's own proven format instead of inventing a new one.
  • Metrics are self-reported via CLI flags, never auto-instrumented. WHY: the engine is stdlib Python with no access to the real session transcript — it cannot see actual token counts or which tools ran. Self-report is the same trust model --details already uses.
  • Stale-worktree check compares a captured HEAD sha, not the plugin version. WHY: a version-string proxy misses staleness when the source commit predates a version bump — sha comparison is exact and catches every case, confirmed live across all three drill rounds this cycle.
  • The search-test step discovers /monitor:search from the project's own docs, not a hardcoded path. WHY: consistent with how the drill's tasks/logging steps already avoid naming commands directly — final review caught the first draft violating this and it was corrected.
