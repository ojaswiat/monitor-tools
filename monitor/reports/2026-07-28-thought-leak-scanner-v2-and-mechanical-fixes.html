Decisions & Rationale

  • Open tasks in the pending gate: folded into the same [Warn!] message pending logs/reports already use, unconditionally and with no invented time threshold — symmetric with existing behavior rather than a new mechanism.
  • Task cleanup ordering: group_tasks() gained a created_at field (the task-start event's own timestamp); clean_tasks() sorts ascending by it instead of relying on activity order. A later verification round found a same-timestamp tie-break bug in this sort and fixed it with a deterministic secondary key.
  • Test suite: pytest, dev-only (requirements-dev.txt, never referenced by the shipped engine), every test against a fresh tmp_path scratch project — never this repo's real monitor/ data.
  • Dashboard search box: one narrow, deliberate exception to the no-JS rule, scoped to index.html only; every other generated page stays script-free. Its initial version had a script-tag-breakout injection risk (a title containing </script> could break out of the embedded JSON), fixed by escaping </>/& before embedding — confirmed by two independent later reviews.
  • Report timestamps: date_created is filled by the authoring agent's judgment, last_modified stamped automatically by --lock-report — reports stay immutable snapshots, only the lock moment is mechanical.
  • Scanner v2 scope split: the scanner redesign went through a full brainstorm/spec/plan cycle (real design decisions: context-capture depth, agentic-verification format, report-only output); the six trailing mechanical fixes were already fully specified one-liners from the final review, so they rode the same subagent-driven-development execution as a fix wave rather than getting a redundant design doc.
  • Scanner v2 architecture: --level scales what context ships with each hit rather than always paying the cost of the deepest search; the skill's agentic-verification step requires an explicit LEAK/OK verdict with reason on every hit rather than an open-ended "read them yourself," and the skill is barred from ever editing a scanned file — only the report output (when requested) is a write.
  • scan_reports(with_text=True) refactor: made optional and default-off so the Dashboard/index callers, which only need metadata, never hold every report's HTML in memory; search_reports() opts in and now frees the text via item.pop("text") immediately after use.

Risks
